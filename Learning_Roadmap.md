# Python Fundamentals Cohort

A 6-week guided practice repo for building Python basics — one small project a week, one branch per student.

Based on a diagnostic assessment, this cohort is working through gaps across **variables, data types, operators, conditionals, loops, lists, and functions**. Each week targets one topic with a small project you can finish in the time between Day 1 and the deadline.

---

## How This Repo Works

- **Branches:** Each student has their own branch off `main`. Work only in your branch — do not push directly to `main`.
- **Folders:** Inside your branch, create a folder per week: `weekN/`. Keep each week's project in its own folder so nothing overwrites previous work.
- **Workflow:**
  1. Topic is introduced on **Day 1** of the week.
  2. Build your project in your branch throughout the week, committing as you go (multiple small commits are better than one big one — it shows your process).
  3. By the **end-of-week deadline**, open a **Pull Request** from your branch into `main`, targeting that week's folder.
  4. Your instructor reviews the PR, leaves comments, and merges once it's solid.
- **Naming:** Name your branch after yourself, e.g. `juan-delacruz`. Name your files clearly, e.g. `week1_profile_card.py`.

```
main
├── student-1-branch/
│   ├── week1/
│   │   └── profile_card.py
│   ├── week2/
│   │   └── grade_classifier.py
│   └── ...
├── student-2-branch/
│   └── ...
└── student-3-branch/
    └── ...
```

## Project Briefs

### Week 1 — Profile Card Generator
Store a person's name, age, GPA, and student status in variables, then print a formatted "profile card" using those variables.
- **Stretch goal:** Use `type()` to print the data type of each variable.
- **File:** `week1/profile_card.py`

## Pull Request Checklist

Before opening your PR each week, confirm:

- [ ] Code runs without errors
- [ ] File is in the correct `weekN/` folder
- [ ] Variable and function names are clear and readable
- [ ] Commit history shows more than one commit (progress, not just a final dump)
- [ ] PR description briefly explains what the code does

---

## Notes

- It's okay if your code isn't perfect — this is about practice and visible progress, not a graded exam.
- Comment your code where the logic isn't obvious; it helps both you and your reviewer.
- If you get stuck, commit what you have and note the blocker in your PR description — partial progress is still progress.
